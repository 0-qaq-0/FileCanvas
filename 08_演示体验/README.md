# 用真实样例演示 FileCanvas

这里的全部文件均为本项目自行生成的虚构样例，不含客户资料、不代表真实成交。

## 最快开始

1. 双击 [打开演示软件.cmd](打开演示软件.cmd)，或打开 [FileCanvas 0.2.0](../07_发布成品/FileCanvas-0.2.0-Windows-x64.exe)。
2. 点击顶部 **体验示例**（欢迎页也有入口）。软件会创建全新的真实文件副本，自动把 20 个文件和 2 个原始子目录加入画布，并保存你的上一项目。
3. 按下面的演示顺序操作。再点“体验示例”即可新开一份，不会覆盖已有演示进度。

也可以手动选择本文件夹下的 [待整理示例](待整理示例)，在左侧勾选并加入画布。它是直接可用的独立样本；软件内的新副本不依赖工作区路径，拷贝 EXE 到其他 Windows 电脑也能创建。

## 一段约 90 秒的展示脚本

时间是录制建议，不是实测效率承诺。

| 操作                                     | 展示重点                 | 可以说的话                                               |
| ---------------------------------------- | ------------------------ | -------------------------------------------------------- |
| 点击“体验示例”                           | 有真实文件，进来就能操作 | “这是一包虚构的内容创作资料，原始文件都还在左边。”       |
| 选中“封面草稿.png”，随意拖动             | 自由布局与真实路径分离   | “我先摆位置，下面两条路径没变。”                         |
| 打开“分类草案”，查看“内容项目”           | 有解释的建议             | “它依据文件名和类型提出建议，不确定的放进待确认。”       |
| 采用草案                                 | 文件归属变化、磁盘不动   | “这里整理的是一份虚拟结构，原始目录还没有变化。”         |
| 进入“02\_创作素材”，调整文件位置或重命名 | 人工修改草案             | “自动建议只是起点，我可以按自己的思路改。”               |
| Ctrl+Z 撤销，再 Ctrl+Y 重做              | 可试错                   | “这些都是虚拟操作，可以撤销；整份分类草案也能一步撤销。” |
| 点击“预览变更”→“结构对照”                | 原结构与目标结构         | “左边是已导入文件的原结构，右边是拟整理后的目录。”       |
| 点击“导出整理方案”→“在文件夹中查看”      | 能拿走讨论和检查         | “导出的是方案和检查结果，不是已经搬完的文件。”           |

主流程预期：当前根层 16 个文件按“内容项目”分到 4 个虚拟文件夹；原来的“临时下载”“旧资料”保持原样。预览有 20 个变更条目（16 个文件路径 + 4 个目录）和 6 个路径未改变的原始条目。变更数不是执行脚本的步骤数。

## 样例包括什么

- 图片：真实 PNG 与原创 SVG，普通图片查看器/浏览器可以打开。
- 资料：UTF-8 Markdown、TXT、带 UTF-8 BOM 的 CSV，可打开阅读。
- 音频：有效 PCM WAV，1 秒简单合成音调；不是人物配音。
- 压缩包：有效 ZIP，内有原创 sample.txt。
- 代码与配置：TS、JSON 文本；FileCanvas 不执行这些文件。
- 未知类型：`.sample`，用于展示保守分类。
- 同名案例：根目录与“旧资料”各有一张“封面草稿.png”，内容不同。把两者放进同一虚拟目录应被拒绝，不覆盖。

样例不是把随机文字改成图片或压缩包后缀。内容、大小与 SHA256 记录在 [样例清单.json](样例清单.json)。

## 加演：同名文件怎样处理

采用“内容项目”草案后，进入“旧资料”，选中里面的“封面草稿.png”，点“移动到…”并选择“02*创作素材”。因为那里已有同名文件，软件应拒绝并提示。取消对话框，把旧文件虚拟重命名为“封面草稿*旧版.png”，再移动即可。最后在预览中核对原路径和新路径；磁盘中的两个原文件都保持不变。

## 反复展示和保存位置

软件内副本位于 `%APPDATA%\FileCanvas\demo-runs\<随机ID>\待整理示例`，每次都新建，不自动删除旧副本。整理进度仍保存在软件的 projects 目录；已导出方案位于 exports 目录。可以通过“打开已保存项目”恢复先前的演示。

部分 Store/MSIX 宿主启动环境会把 AppData 写入重定向到系统管理的 LocalCache。程序会解析演示与导出的真实位置：点击“查看原文件夹”或导出后的“在文件夹中查看”即可定位，不必手动猜路径。切换不同宿主启动方式可能显示不同的系统数据视图；需要继续同一项目时，请保持启动方式一致，或先导出方案保留记录。

**当前未开放真实移动和真实恢复。** 展示时不要说“一键整理硬盘完成”“AI 理解文件内容”或“百分之百可回滚”。样例里标注“交付”的文件名也只是规则演示，不代表发生过真实交付。
