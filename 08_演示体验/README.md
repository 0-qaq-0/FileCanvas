# 用虚构样例演示 FileCanvas

这里的文件由本项目自行生成，不含客户资料，不代表真实成交。当前版本已支持确认后的真实移动与最近一次恢复，旧版“只演练、不执行”的说明已不适用。

## 开始

1. 双击 [打开演示软件.cmd](打开演示软件.cmd)，或直接启动从 [Releases](https://github.com/0-qaq-0/FileCanvas/releases/latest) 下载的 EXE。免安装版无需 Node.js；继续改代码可以用根目录的 [启动开发版.cmd](../启动开发版.cmd)。
2. 首次点击 **先用 20 个示例文件试一遍**。已经进入画布时，使用 **更多工具 → 体验示例**。
3. 软件创建新的真实样例副本，自动将 20 个文件和 2 个原始子目录加入画布。每次重新体验都会新建，不覆盖已有进度。

也可手动选择本目录下的 [待整理示例](待整理示例)，但应用操作会实际改变你所选择的目录；建议使用软件内新副本演示。内置样例不依赖项目工作区，把 EXE 复制到其他 Windows x64 电脑后也能创建。

内置“内容项目”草案会将根层 16 个文件分到 4 个新分类目录，原来的“临时下载”“旧资料”保持原样。本轮打包验收已走完整个流程：16 个文件真实移动，全部 20 个文件内容摘要一致；恢复后原目录树与内容摘要一致。

若只是展示方案，也可以在预览中使用 **导出整理方案**。导出本身不移动文件。

## 样例内容

- 图片：有效 PNG 与原创 SVG。
- 资料：UTF-8 Markdown、TXT、带 UTF-8 BOM 的 CSV。
- 音频：有效 PCM WAV，短合成音调。
- 压缩包：有效 ZIP，内含原创文本。
- 代码与配置：TS、JSON；软件不会执行这些内容。
- 未知类型：`.sample`，用于展示需要人工判断的情况。
- 同名文件：根目录与“旧资料”中各有不同内容的“封面草稿.png”。

独立样例的内容、大小与 SHA256 见 [样例清单.json](样例清单.json)。当前预览支持图片和文本；音频、压缩包、PDF、Office 等未提取正文，不应在演示中说它们已被完整理解。

## 同名冲突展示

采用草案后，尝试把“旧资料”内的“封面草稿.png”移动到已有同名文件的“02\_创作素材”。软件应提示冲突；改成不同名称后再检查。不覆盖同名目标，移动计划必须经“检查并应用”确认。

## 保存位置与范围

EXE 内置副本默认位于 `%APPDATA%\FileCanvas\demo-runs\<随机ID>\待整理示例`，每次新建，不自动删除旧副本；项目在 `projects`，方案导出在 `exports`。开发运行使用独立的 `%APPDATA%\FileCanvas-Development`，不会自动同步到 EXE。

部分 Store/MSIX 启动环境可能重定向数据目录。可以从软件内的“查看原文件夹”等入口定位实际位置；保留未完成任务对应的数据和恢复区。

当前限同一授权本地根目录，建议 NTFS，每次最多移动 100 个文件；不支持跨盘、网络共享和链接目录整理。恢复路径不等于文件正文备份。完整说明见 [EXE 使用与交付说明](../05_项目文档/0.4.0EXE使用与交付说明.md)。
