# FileCanvas：竞品调研与卖点判断

调研日期：2026-10-16。范围：5 个相关产品 + Windows 资源管理器这一免费替代。信息来自开发者页面、官方文档和公开仓库说明；没有安装并实测竞品，也没有核验其付费交易、用户数量、恢复成功率或实际性能。以下区分“官方功能说明”“本项目实测”“产品推断”和“待验证需求”。

## 结论先看

**当前最值得验证的定位：Windows 文件整理演练台——先拿到草案，再自由微调，看清路径，导出方案。** 适合尚未想好分类方式、需要向他人解释整理方案的单个资料包场景。

这是一种产品聚焦，不能宣称市场上独有。自由画布、预览、撤销、中文、本地运行和规则分类都已有替代。FileCanvas 目前也不能真正把硬盘整理完成；若用户只想一键搬好文件，现有版本不满足其核心需求。这是付费转化的重要短板。

本次优先把“整理思路能试、能改、能核对、能展示”做完整，不把尚未开发的真实执行和恢复写成卖点。完成阶段二后，才有资格验证“可视化规划 → 安全执行”的完整价值。

## 哪些话不能当卖点

- “全球首个自由文件画布”：没有证据，且已有同类。
- “只有我们不动原文件”：标签类产品也能在不改文件名的前提下组织文件。
- “AI 理解全部文件”：当前仅按名称和扩展名分类，不读取文件内容、不调用模型。
- “一键安全整理完成 / 100% 恢复”：真实移动和真实恢复尚未开放。
- “成熟商用、已有付费客户、节省 80% 时间”：本项目没有对应证据。
- “免费竞品功能多，所以没人会用”：同样没有需求验证证据；应验证具体用户是否需要演练流程。

## 建议突出什么

| 可展示价值                 | 谁可能在意（待验证）                   | 本次实现与可检查证据                                          | 当前边界                                             |
| -------------------------- | -------------------------------------- | ------------------------------------------------------------- | ---------------------------------------------------- |
| **先演练，后决定**         | 怕整理错、目录结构还没想好的人         | 草案只改变虚拟模型；采用草案可以一次撤销；原目录哈希验证      | 现阶段没有“后执行”，只能演练和导出方案               |
| **建议能解释，也能改**     | 不想配置复杂规则的个人用户             | “内容项目/按类型”两套草案，逐项显示理由；未知用途进待确认     | 名称规则会误判，尤其是“最终/定稿”等词；需要人工复核  |
| **原位置与拟放位置看得见** | 整理课程资料、创作素材、交接资料包的人 | 选中卡片的双路径核对栏，预览逐项路径和前后目录树              | 只包含已经加入画布的条目，未加入文件不在方案里       |
| **方案可以拿走讨论**       | 要让同学、搭档或客户看懂结构的人       | 导出 Markdown，包含结构对照、路径清单、冲突和未执行说明       | 文件名仍可能敏感；方案不包含文件内容，也不是执行脚本 |
| **小白可以先用样例试**     | 第一次打开工具的人                     | 20 个真实文件样例；每次创建新副本并自动导入，演示不碰个人资料 | 仅一种虚构内容项目；不代表所有文件格式都支持预览     |

中文、无需账号、程序自身不上传文件、项目数据保存在本机，是这套体验的配套条件。它们不能单独证明用户愿意付费，也不能替代数字签名、可靠执行与真实恢复。

## 本次修改优先级

1. 已做：可解释分类草案、一次撤销整份草案；保留原始子目录，不递归擅自分类所有文件。
2. 已做：卡片双路径核对、整理前后树形对照。
3. 已做：导出可阅读的方案，导出时重新检查磁盘，冲突也随方案导出。
4. 已做：工作区 `08_演示体验/待整理示例` + 软件内“体验示例”独立副本。
5. 保持未开放：真实移动、删除、真实恢复；继续维持阶段一的文件边界。

具体文件、测试和演示方式见 [修改与验证记录](02_修改与验证记录.md) 和 [演示指南](../../08_演示体验/README.md)。

## 怎么判断这个定位有没有用

优先找有“一次性资料包整理”任务的人，而不是泛泛询问“你喜欢文件管理软件吗”。首轮建议邀请 3–5 位同学或内容创作者，用非敏感样本观察完整流程；这是待执行验证计划，不是已完成访谈。

记录：任务、原本方法、为什么迟迟没整理、是否需要先讨论目录结构、第一次分类误判数、手动改动数、理解双路径所需时间、是否导出方案，以及最希望补上的功能。

最关键的反证：若大多数人明确表示“没有真实执行就没用”，应优先评估阶段二，或把演练功能定位成完整整理工具的一部分；不能继续把限制包装成强需求。

当前不建议仅凭竞品价格给本项目设定售价。先完成试用和需求记录，再决定是免费工具、完整整理软件，还是用于文件整理服务的辅助工具。没有付款或接受交付的证据，就没有已验证商业收入。
