## 检查方式与证据

- `npm.cmd test`：36 项测试，包含分类理由、目的目录复用、冲突拒绝、整份撤销/重做、前后树形推导、Markdown 边界和样例文件保持不变。
- `npm.cmd run test:e2e`：原阶段一完整交互回归，结果为 `03_测试结果/acceptance.json`。
- `npm.cmd run test:demo`：新演示流程实测，结果为 `03_测试结果/demo-acceptance.json`。验证创建样例、真实鼠标拖动、分类草案、一次撤销/重做、双路径、结构对照、报告导出和重复创建副本。
- 演示流程中，前后逐项比较路径、文件大小、mtime 和 SHA256；一致。报告写入另一个 exports 目录，不计入原始样例目录。
- 新写入边界检查：在隔离临时数据目录中把 exports、demo-runs 替换成目录联接；程序均拒绝写入，联接指向的外部测试目录保持为空。此部分是额外的故障模拟，与正常演示的源目录不变检查分开进行。
- 当前演示中有 20 个真实文件、2 个原始子目录；当前层 16 文件分类到 4 个虚拟目录，预览 20 项变更、6 项路径未改变、0 项检查问题。
- 截图：`demo-draft.png`、`demo-structure.png`、`demo-workspace.png`、`demo-compact.png`；自动测试导出的方案副本：`03_测试结果/演示整理方案.md`。

正式 EXE 检查发现了开发模式未复现的 AppData 重定向：当前 Store 宿主启动的进程创建文件后，实际路径落在 LocalCache，原逻辑路径不能继续当作授权根。已在创建演示后解析真实根目录，并将导出返回位置解析为实际文件路径；没有取消路径边界和目录联接拒绝。该现象与微软所述 [MSIX 文件系统虚拟化](https://learn.microsoft.com/en-us/windows/msix/desktop/desktop-to-uwp-behind-the-scenes) 相符，实际重定向还受启动环境影响。

## 最终发布程序验证

`npm.cmd run package:win` 已生成 0.2.0。`node 02_测试/启动检查/smoke-package.mjs --demo` 在真实打包程序中完成创建样例、分类、结构对照与导出检查，20 个源文件的 SHA256 保持一致；`package-smoke.json` 中 `demoChecked` 为 true。随后便携 EXE 的两种启动/关闭时序检查通过。

成品：`07_发布成品/FileCanvas-0.2.0-Windows-x64.exe`，86,774,429 字节；SHA256：`45CD8328DE96A3BD33BF8DE954354A715FECB76CC8DB9DEDECAA10941E737FFE`。数字签名状态为 NotSigned。0.1.0 EXE 保存在历史版本目录。

最后实际执行了 `08_演示体验/打开演示软件.cmd`，主窗口成功显示。Windows 批处理使用 UTF-8 和 CRLF 换行，避免仅 LF 换行在切换代码页后导致命令被截断；`.gitattributes` 已固定此规则。

样例文件的 PNG、WAV、ZIP 是有效格式，文本、CSV、JSON 可正常阅读或解析；这不代表 FileCanvas 提供这些文件的内容预览。目前卡片仍主要显示图标。

## 已知限制

真实移动、真实恢复、任意内容理解、自动去重、递归擅自分类子目录、真实付费案例、竞品性能优劣均未作为本次成果。用户在资源管理器中做的外部修改由用户自己决定；软件的实时预览只检查已有的几类冲突与源变化。

0.1.0 是初始阶段一基线，0.2.0 是产品演练流程版本；历史验收记录保留，新增证据归入本次结果。Windows 10 未独立实机验证，EXE 未签名，部分权限情况仍为错误码模拟，不能把测试通过解释为任何情况下都安全可恢复。
