# FileCanvas 0.3.0：画布与 AI 改版

日期：2026-10-16。当前交付为 Windows 桌面应用，保留原文件只读边界。

## 直接体验

运行 `07_发布成品/FileCanvas-0.3.0-Windows-x64.exe`。欢迎页可先使用示例；再次创建示例的入口在右上角“更多工具”。

1. 打开文件夹，文件自动加入画布；超过导入上限或遇到不可读取条目时，从文件栏分批导入。
2. 单击卡片在本窗口查看内容。图片显示缩略图，文本显示片段，文件夹卡片显示两个内部名称；预览栏可逐项查看内部文件，双击文件夹才进入该层画布。
3. 拖动卡片排列，拖进文件夹分类。重命名用 F2。“专注画布”收起顶部和辅助栏，右上角“退出专注”返回。
4. 文件栏、预览栏和 AI 助手均可收起；当前目录的 AI 对话收起后仍保留，切换目录或项目重置对话。
5. “预览变更”核对结构和路径，必要时导出方案。“应用到硬盘”仍未开放。

## 模型配置

AI 助手 → 配置模型 → 选择常用服务或自定义兼容接口 → 编辑地址、模型名称、密钥 → 保存并测试连接。

| 服务     | 预设地址                    | 模型填写方式                                                                    |
| -------- | --------------------------- | ------------------------------------------------------------------------------- |
| OpenAI   | `https://api.openai.com/v1` | 使用账号可调用的模型名称；可从预设选择或手填                                    |
| DeepSeek | `https://api.deepseek.com`  | 默认 `deepseek-flash`，可编辑                                                   |
| Ollama   | `http://127.0.0.1:11434/v1` | 使用已经下载到本机的模型名称，密钥通常留空                                      |
| 自定义   | 自行填写                    | 支持 Chat Completions 的兼容服务；填基础地址，不填完整 `/chat/completions` 路径 |

地址和模型名始终可编辑，服务名只提供便捷填充。地址需用 HTTPS，本机回环地址允许 HTTP。切换服务地址时不会沿用旧服务的密钥。密钥经 Electron safeStorage 在本机加密，保存于 `%APPDATA%/FileCanvas/ai-settings.json`，不会写入项目 JSON，也不会回显给前端；可勾选清除密钥后保存。系统加密不可用时拒绝保存密钥。

“测试连接”发送一条测试语句并可能产生服务商调用费用；不会发送项目文件。真实服务是否能使用还取决于账号权限、模型兼容性、额度和网络。本次自动验收使用本机模拟接口，不声称已验证云模型效果。

## 问文件、查资料与 AI 整理

选中文件或文件夹，打开 AI 助手；未选择时分析当前目录及其子树。可以描述具体目标，例如“这次拍摄要交付什么？哪些材料应该放在一起？”

- **问文件 / 查资料**：准备文件信息、所选文本片段及本地检索结果，展示将发送的资料；确认后调用模型，要求回答列出证据的相对文件路径，并区分正文证据与文件名推测。
- **建立 / 更新索引**：只在本机读取当前项目的文本，支持检索未加入画布的文件。索引保留在当前运行的内存中，切换项目清空；重启后需重建，外部文件变化后需更新。
- **AI 整理**：只分类当前画布层级的文件，保留文件名和原文件路径。先展示文件夹、文件清单与理由；采用后形成一笔虚拟事务，Ctrl+Z 一次撤销。文件夹内部要进入后再分类。

每次请求前都可以检查文件清单及实际正文片段；勾选后才发送到已配置服务。最多附带最近六条问答，界面会标明。隐藏项、常见密钥文件、依赖和构建目录不读取正文，但文件名仍可能出现在你选中的清单里。任意普通文档里可能包含私人信息，因此发送前仍要检查实际片段。

模型没有文件修改工具，也不能执行文件里的指令。返回方案会校验文件 ID、重复项、文件夹名称和当前画布版本；范围外、重复、非法路径等方案不会采用。无法保证模型所有建议都正确，需要核对展示的理由。

## 本次已实现的格式和规模

| 能力                        | 当前范围                                                                                                  |
| --------------------------- | --------------------------------------------------------------------------------------------------------- |
| 文本预览与正文检索          | TXT、Markdown、CSV/TSV、JSON、YAML、TOML、INI、日志、XML、HTML、常见代码等；UTF-8，支持带 BOM 的 UTF-16LE |
| 图片本地预览                | PNG、JPG、GIF、WebP、BMP，单张最多 5 MB；本次不向 AI 发送图片                                             |
| PDF、Office、音视频、压缩包 | 文件信息可见，未提取正文，也无 OCR；明确提示未读取                                                        |
| 单文件读取                  | 最多读取 256 KB；保留前 24000 字符用于预览或分块，截断会提示                                              |
| 项目索引                    | 最多遍历 6000 项、1000 份文本、4000 个片段；达到上限会提示部分覆盖                                        |
| 单次问答                    | 最多 100 项信息、8 段正文，每段最多 1800 字符；当前为关键词检索                                           |
| 画布与文件导入              | 最多 5000 个节点；大目录导入失败时可从文件栏分批加入                                                      |

选择更多文件不意味着 AI 读过所有正文；界面会显示未提供正文的文件数量。当前是有明确边界的项目检索版本，没有实现全盘扫描、持久化向量库或后台文件监听。

## “让 AI 了解整个电脑”的研究结论与后续方案

不建议每次把全部文档直接附到问题后面：文件越多，读取时间、请求体积和费用越大，而且无关资料可能干扰回答。更合适的方案是**按目录授权 → 提取正文 → 分块建索引 → 检索相关片段 → 带来源回答**。OpenAI 的 [Retrieval 文档](https://developers.openai.com/api/docs/guides/retrieval)说明了语义检索与向量库；[File Search 文档](https://developers.openai.com/api/docs/guides/tools-file-search)提供托管检索能力。

本次先实现本机关键词索引和限定范围问答，下一阶段可以分三步扩展：

1. **多目录本地知识库**：由用户勾选具体文档目录，建立 SQLite 清单，记录路径、修改时间、内容摘要与排除规则；变动文件增量更新，删除文件同步移除，检索时重新验证路径授权和文件有效性。结果是 AI 可以跨项目找资料，而不是默认读取所有磁盘。
2. **PDF / Office 提取与混合检索**：为 PDF、DOCX 等增加隔离的正文提取，扫描件按需 OCR；文字按段落分块，关键词检索与本机或云端 embedding 结果合并排序。结果是语义相近但用词不同的资料也能被找出，仍保留路径、页码和原文证据。接入前需要验证解析质量、耗时、索引磁盘占用与模型费用。
3. **目标与长期偏好**：增加由用户填写的项目目标、交付要求和可编辑偏好；每次只检索与目标相关的资料，展示“为什么推荐这一类”。结果是建议更贴近用途，但不会把模型猜测保存成用户事实。

可选部署方式：完全本机时，文档提取、索引和本机模型都留在电脑，效果及速度取决于硬件与模型；本机索引加云模型时，仅发送确认过的片段，通常更容易更换模型；托管 File Search 则需要向服务商上传文档，须另外设计上传授权、删除及成本展示。本次采用“本机索引 + 可配置模型”，没有上传整份知识库。
