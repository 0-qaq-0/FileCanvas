# 自定义规则（“我的规则”）实现与验证

日期：2026-10-20。接在 [同类产品调研与易用性优化](同类产品调研与易用性优化_2026-10-20.md) 之后，补上调研里列出的差距“没有用户自定义并保存的规则”。磁盘引擎（`electron/disk-operations.ts`）**没有改动**。

## 1. 能做什么

“分类草案”里多了第五种方式“我的规则”。用户写规则，例如“名称含‘发票’或扩展名 pdf → 财务/发票”，保存后在任何文件夹里都能用，预览和采用方式与其他四种完全一致：

- 按目标文件夹分组，显示数量、“新建文件夹 / 放入已有文件夹”，可展开看每个文件和命中理由；
- 每组一个开关，关掉的组原地不动；
- 采用后只改画布，一次撤销；真实文件要等“检查并应用”。

## 2. 规则怎么算

一条规则：`{ id, name, match: { keywords?, extensions?, olderThanDays?, minSizeMB? }, folder }`。

- **关键词与扩展名是“或”**：名称含任一关键词（不分大小写），或扩展名在列表里，都算满足；两者都没写则这一项不限。
- **天数与大小是“且”**：写了“多少天没改过”或“大小不小于 N MB”，文件还必须同时满足。天数边界与“久未修改归档”一致（满 N 天算）；没有修改时间或大小的文件不会被这类条件命中。
- **至少要有一个条件**，否则不能保存（避免一条规则吞掉所有文件）。
- **按列表顺序，第一条命中的生效**；谁也不命中的文件留在原处，没有“其他”文件夹。
- **文件夹可以写多层**：`财务/发票`，`/` 或 `\` 都行，空段会忽略；每一段按画布的文件夹命名规则检查（保留名、非法字符、末尾句点、过长都会拒绝，最多 6 层）。已有的同名文件夹不分大小写复用，只创建缺的那一段；某一段被同名文件占用、或目标里已有同名文件，会像其他方式一样给出提示，整份草案不采用。
- 两条规则写了大小写不同的同一文件夹（`Docs` 与 `docs`）合并成一组，用先出现的写法显示。

规则只读文件名、扩展名、修改时间和大小，不读内容，也不上传任何东西。

## 3. 保存在哪里

`<应用数据目录>/rules.json`：`{ "version": 1, "rules": [...] }`，用 `writeAtomic` 原子写入。不用渲染进程的 `localStorage`（开发版与打包版来源不同，互相看不到）。

- 读取和保存都用同一个校验函数；保存时主进程会重新校验渲染进程传来的内容（最多 50 条，名称、关键词、扩展名、天数、大小、文件夹都有上限）。保存请求排队执行，不会交叉写临时文件。
- 文件损坏（不是 JSON、格式或某条规则无效、超过 1 MB）：改名为 `rules.damaged-<时间>.json` 保留，列表从空开始，并在界面提示。不会直接覆盖。
- 文件的 `version` 大于 1（更新版本写的）：既不读取也不覆盖，界面显示错误，避免旧版本把新规则弄丢。
- 对话框里的列表是“当前真相”，每次改动立即保存；保存失败会提示“规则没能保存”，本次仍可使用。第一次选“我的规则”时才读文件。

开发版（`FileCanvas-Development`）与打包版（`FileCanvas`）的应用数据目录不同，所以两者的规则各存各的；开发版不会像 `ai-settings.json` 那样首次复制打包版的规则。

## 4. 界面

`RulesEditor`（`01_源码/src/components/RulesEditor.tsx`）在“我的规则”下显示：

- 规则列表：序号、名称、条件摘要、目标文件夹、**“命中 N 个”**（当前层有多少文件最终归入这条规则）；如有文件满足条件却被前面的规则先拿走，另注“另有 M 个已被前面的规则归类”。
- 上移 / 下移（调整优先级）、编辑、删除（删除要再确认一次）、添加规则。
- 编辑表单：规则名称、目标文件夹、名称包含的关键词、文件扩展名、至少多少天没改过、大小不小于多少 MB；实时显示“按这些条件，当前层会有 N 个文件符合”；条件不合法或名称与已有规则重复时提示并禁用保存。Esc 只关闭表单，不会关掉整个对话框。
- 对话框内容区整体可滚动，底部“采用草案到画布”始终可见；原有对话框标题、`分类草案`、`采用草案到画布` 等名称没有变。

## 5. 验证

- 单元测试 182 项通过（其中新增 71 项）：
  - `rules.test.ts`：命中（含天数边界日、缺少修改时间、大小边界）、“或/且”组合、先命中先生效、路径与扩展名规范化、非法规则和文件夹（`con`、`a/../b`、句点结尾、过深）、实时命中数、嵌套文件夹只创建一次、不同大小写复用、段被文件占用、目标已有同名文件、关闭某组、一次撤销、在子文件夹层使用。
  - `rules-storage.test.ts`：无文件、往返、规范化存储、拒绝非法保存且不改旧文件、损坏/版本无效/规则无效/超大文件改名保留、保存时保留损坏文件、新版本文件不读不覆盖、重叠保存按顺序、失败后可继续。
- `npm run test:smart` 增加两段，在 1000×680 窗口里走：打开“我的规则” → 添加三条规则（含 `财务\发票` 与“全部 PDF”）→ 看命中数与“被前面规则抢先”→ 同名提示与 Esc → 上移/下移改变命中 → 删除确认 → 读取磁盘上的 `rules.json` 确认版本和内容 → 采用（`12 个文件 · 3 个文件夹`）→ Ctrl+Z → 重开对话框能读回规则 → 整个过程磁盘摘要不变。**最后再做一次真实应用**：引擎在磁盘上建出 `财务/发票/` 与 `归档/`，逐个文件核对 SHA-256，未命中的文件原样，随后恢复，目录树与原始摘要完全一致。
- `test:demo`、`test:expanded` 仍通过；截图在 `03_测试结果/智能整理`（本机证据，不入库）。

## 6. 没做的、有限制的

- **没有真人试用**。规则语言是否被看懂（“或/且”的组合、`/` 表示多层）只是设计判断。
- 规则只作用于**当前画布层的文件**，和其他四种方式一致；不递归、不读内容、不支持正则、日期条件只有“多久没改”、没有“排除”条件。
- 规则只在“分类草案”里手动运行；没有监视和自动运行，也没有规则的导入导出。
- 没有重新打包 EXE，也没有跑 `smoke-package`/`smoke-portable`；e2e 只在源码构建的 Electron 里跑过。
- 界面组件没有单元测试（项目里没有渲染测试设施），靠上面的桌面 e2e 覆盖。
- 暂时没有“建议条”里的“用我的规则整理”入口，需要先点“分类草案”。
