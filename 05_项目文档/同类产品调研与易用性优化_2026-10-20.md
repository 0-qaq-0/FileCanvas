# 同类产品调研与易用性优化

日期：2026-10-20。接在 [成熟产品路线图](成熟产品路线图_2026-10-20.md) 和 [0.4.1 可靠性改进记录](0.4.1可靠性改进记录.md) 之后。这一轮做两件事：看同类产品怎么做、把“整理文件”这条主线改得更顺手。

**证据说明。** 竞品信息来自厂商主页、开源仓库说明和第三方汇总，**没有安装试用任何一款**，没有核验价格现状、用户数量、恢复成功率或性能。汇总页 Fast.io 本身是它所评测的工具之一，只作线索。搜索摘要里的信息单独标注。更早的调研见 [竞品调研与卖点判断](产品调研/01_竞品调研与卖点判断.md)。

从这些页面能看出几个共同点：

1. **先审阅再动手**是 AI 整理类工具的标配，而且审阅的单位是“目标分类”，用户可以改。
2. **规则**是传统工具的核心（Hazel、File Juggler、DropIt），门槛是要自己写；AI 工具想用自然语言取代它。
3. **常驻监视**（Hazel、File Juggler、Sortio、NameQuick）把整理变成习惯；一次性工具（AI File Sorter）靠“一键整理”赢第一印象。
4. **重复文件、旧文件清理**常和整理放在一起卖。

## 2. 这一轮改了什么

围绕一个观察：打开自己的“下载”文件夹后，用户面对一屏卡片，不知道下一步做什么；找到的“分类草案”默认是为演示项目写死的“策划资料 / 创作素材 / 交付成品”，真实的下载目录几乎全落进“99\_待确认”。

| 问题                         | 改动                                                                                                                                                                              | 对应同类做法                         |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| 打开后不知道做什么           | 画布上方出现可关闭的建议条：“这一层有 12 个散放文件，先试试一键整理？”，给出会真正改变结果的方式；只在计划未改动时出现                                                            | 一键整理的第一印象                   |
| 默认分类只适合演示           | 默认“按文件类型”（演示项目仍默认“内容项目”）；类型表拆出 PDF、表格、演示、电子书、安装包、设计文件、字体；新增“按修改月份”“久未修改归档”（30/90/180/365 天）                      | Sparkle、File Juggler 的日期条件     |
| 预览是一长串文件，看不出结构 | 按目标文件夹分组，显示数量、“新建 / 放入已有文件夹”，可展开看每个文件和理由；每组一个开关，关掉的组原地不动                                                                       | 审阅对话框里改分类（AI File Sorter） |
| 选一批文件放进新文件夹要三步 | “移入新文件夹”（Ctrl+Shift+N）：建在选中项所在位置，一次撤销，默认名取自文件类型                                                                                                  | Finder 的“用所选项目新建文件夹”      |
| 大目录里找不到文件           | Ctrl+F 筛选：不匹配的淡出，含匹配的文件夹有提示，显示匹配数；“选中匹配项”（或回车）直接选中，之后可移动、新建文件夹、重命名                                                       | Hazel 的规则预览思路                 |
| 改名只能一个一个来           | 批量重命名（多选后 F2）：查找替换加模板 `{name} {n} {date} {parent}`，序号可设起点和位数；扩展名始终保留；实时“原名 → 新名”表，非法名称、未知占位符、与同层重名都会标出；一次撤销 | Advanced Renamer 一类的批量改名器    |
| 常用动作藏在小图标里         | 卡片右键菜单：查看内容和解释、用系统应用打开、在资源管理器中显示、移到…、移入新文件夹、重命名、移出画布；Esc、方向键可用                                                          | 文件管理器通用习惯                   |

三个组合起来的典型路径：**搜“发票” → 选中匹配项 → 移入新文件夹 → 批量重命名 → 检查并应用**。

### 验证

- 单元测试 111 项通过，其中新增 42 项：各配方（含按月分组、旧文件时钟注入、已有文件夹复用、重名拒绝）、新建文件夹、筛选、批量重命名（含根目录 {parent} 与空名称两处自查修复）。
- 新增桌面检查 `npm run test:smart`：在 1000×680 窗口里用一个下载风格的 12 文件夹走完“建议条 → 右键菜单 → 分组预览并关闭 PDF 组 → 采用/撤销/重做 → 筛选 → 选中匹配项 → 移入新文件夹 → 批量重命名（含非法名称禁用）→ 应用 → 逐个核对真实路径和 SHA-256 → 恢复”，目录树与原始摘要完全一致。截图在 `03_测试结果/智能整理`（本机证据，不入库）。
- 原有 `test:demo`、`test:expanded` 仍通过；演示项目仍默认“内容项目”，`分类草案`“采用草案到画布”等按钮名未变。
- 开发中自查出两处：重复点击当前配方会清掉用户关的分组（已改为不重置）；调整分组显示顺序时一度让“文件占用了分类文件夹名”的检查失效（已按首次出现顺序创建文件夹，原用例重新通过）。
- **没有真人试用。** 这些改动是否“更符合直觉”还只是设计判断，需要第 4 节的试用来验证。

## 3. 我们的优势在哪里

先说**能站得住**的：

1. **先看清终态再动手，而且是看得见的。** 同类 AI 整理工具的审阅多是列表对话框；我们把终态放在画布上，可以拖、可以展开、可以改，预览里还有整理前后的目录树对照，并能导出 Markdown 方案给别人看。这是“好理解”而不是“功能多”的优势。
2. **应用可核验、中断可恢复，且有证据。** 每次应用有日志、执行后重新核对路径和文件内容，80 个“中断点”恢复用例和真实桌面流程都通过。对比：AI File Sorter 自述撤销是“尽力而为”。注意边界：测的是进程退出，不是断电；恢复的是路径，不是内容的历史版本；只验证了 NTFS。
3. **本地优先、无账号、AI 可选。** 不配置 AI 时全部功能可用；配置后文本只在用户允许后发给自己指定的服务或本地 Ollama。对比：据搜索摘要 Sparkle 会把文件名发给其服务器和 OpenAI，Filect 会把内容发给 OpenAI。AI File Sorter、AI File Organizer Pro 也支持本地模型，所以这点不是独有，是“门槛”。
4. **规则可解释、可局部关闭。** 每组附理由，可展开，也可整组关掉。
5. **Windows 原生、当前免费。** Hazel、Sparkle 只有 Mac；File Juggler 要付费。没有证据显示用户因此会选我们，只是定位上的空位。

**不能说的：** “唯一的画布整理工具”（Canfolds 已存在）；“最安全”（没有对手对比测试）；“中文唯一”（没有逐一核实竞品界面语言）。

**要正视的差距：**

| 差距                                                                                                           | 谁有                                           |
| -------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| 没有常驻监视与自动运行                                                                                         | Hazel、File Juggler（定时）、Sortio、NameQuick |
| 读不了 PDF、Office 正文                                                                                        | File Juggler、AI File Sorter（读文档文本）     |
| 没有重复文件检测                                                                                               | Sparkle（搜索摘要）                            |
| ~~没有用户自定义并保存的规则~~（已补，见[自定义规则说明](自定义规则实现与验证_2026-10-20.md)；仍不能自动运行） | Hazel、File Juggler、DropIt                    |
| 没有安装器、签名、自动更新                                                                                     | 几乎所有商业产品                               |
| 没有真实用户验证                                                                                               | —                                              |

结论：我们现在适合定位成“**能看懂、敢点确定的一次性整理台**”，而不是 Hazel 式的后台自动化；要走向后者，缺口是监视、自定义规则和内容读取，不是画布。

## 4. 没做、建议接着做

按“少一点改动、多一点价值”排：

1. **真人试用 3–5 人**（沿用路线图第 5 节），重点观察：打开后是否点了建议条、是否用右键、是否用 Ctrl+F。没有这一步，上面的“更直觉”无法证实。
2. **自定义规则**（“名称含‘发票’ → 财务/发票”，可保存、可复用、先预览）：同类产品的核心能力，也是建议条的自然延伸。**已实现**：规则存在应用数据目录的 `rules.json`（不用 `localStorage`），做法和验证见 [自定义规则实现与验证](自定义规则实现与验证_2026-10-20.md)。
3. **重复文件**：先按大小、再按头尾片段、最后整体哈希，归入“重复文件”文件夹而不删除。暂缓原因：要新增主进程接口，要整体读文件（云盘占位文件可能触发下载，见路线图 P0-4），还要决定保留哪一份。
4. **拖入文件夹打开**：直觉很强。暂缓原因：自动化测试里的模拟拖放拿不到系统路径，无法验证。
5. **常驻监视下载文件夹**：路线图 P1-1，决定权在试用结果。
6. PDF、Office 正文提取，以及安装器和签名：路线图 P1-7、P2。
