# 界面设置（2026-10-20）

顶部滑块图标（或 `Ctrl+,`）打开“界面设置”。它是停靠在右侧的面板，画布保持可见、可操作，所以拖动滑块时能直接看到效果；改动立即生效并自动保存，只影响显示，不会改动计划或任何真实文件。

## 有哪些设置

| 设置         | 选项               | 说明                                                                                                     |
| ------------ | ------------------ | -------------------------------------------------------------------------------------------------------- |
| 图标大小     | 70%–160%，每格 5%  | 滑块；“小 80% / 标准 100% / 大 125% / 特大 150%”快捷按钮；在画布上按住 Ctrl 滚动滚轮同样可调（每格 ±5%） |
| 画布背景     | 点阵 / 网格 / 纯色 |                                                                                                          |
| 卡片预览     | 开 / 关            | 关闭后卡片只显示图标，不再读取文件生成缩略图和文档摘要，文件很多时更轻快                                 |
| 整理建议条   | 开 / 关            | 文件夹里散放文件较多时顶部的一键整理提示                                                                 |
| 底部操作提示 | 开 / 关            | 画布下方的快捷操作说明                                                                                   |
| 减少动画     | 开 / 关            | 去掉淡入、滑动等过渡（系统本身要求减少动画时，这一项原本就已生效）                                       |

“恢复默认”一键还原全部；已经是默认值时按钮置灰。

## 图标大小是怎么实现的

画布的布局、命中判断和拖放都按“画布坐标”计算，卡片尺寸（136×138）、文件夹容器的内边距、整理对齐的 156px 间距等常量散落在 `canvas-layout.ts` 和 `ExpandedCanvas.tsx` 里，而且已保存项目里每张卡片的坐标就是这套像素值。所以图标大小**不改这些数字**，只把整个画布面用 `transform: scale()` 放大或缩小：

- `point()` 把指针位置除以缩放后再参与计算，所以 150% 下拖进文件夹的落点、框选、外部拖入都仍然准确。
- 可见区域（`viewport`）也按缩放换算，因此“排列整齐”的列数、自动展开布局的可用宽度随缩放变化。
- 画布外包一层按缩放后尺寸设定大小的容器（`overflow: clip`，不是 `hidden`，以免它变成滚动容器而破坏“放入：…”提示的吸顶），缩小时才不会多出滚动区。
- 缩放时以当前视图中心为锚点；视图在顶部或左侧边缘时就留在边缘。

结果：同一个项目换任何图标大小，卡片的相对位置都不变，不会出现放大后互相压住。

## 存储

`preferences.json` 在应用数据目录，和 `rules.json` 同一目录、同一套做法（不用 localStorage：开发版和打包版是不同来源）：

```json
{
  "version": 1,
  "preferences": {
    "iconScale": 1.25,
    "background": "grid",
    "showPreviews": true,
    "showHints": true,
    "showSuggestions": true,
    "reduceMotion": false
  }
}
```

- 原子写入；渲染进程传来的值在主进程再校验一次（`domain/preferences.ts`，缺失或非法的字段逐项回到默认，未知字段丢弃，不会抛错）。
- 文件损坏（不是 JSON、版本无效、超过 64KB）：改名为 `preferences.damaged-<时间>.json` 保留，使用默认值并弹出提示，不覆盖。
- 来自更新版本的文件：不读取、也不覆盖（显示默认值并提示；此时新的修改无法保存，会提示保存失败）。
- 拖滑块时 300ms 去抖后保存；关闭窗口的握手流程会先把尚未写出的修改落盘。

## 展示方式（画布 / 平铺 / 列表 / 分组）

导航栏右侧的切换按钮，也可在界面设置的“展示方式”里选。四种方式看的是**同一份整理计划**，只是排法不同：

| 方式 | 排法                                                                                           | 适合                           |
| ---- | ---------------------------------------------------------------------------------------------- | ------------------------------ |
| 画布 | 自由摆放，保留你拖出来的位置；文件夹可原地展开成容器                                           | 先想清楚结构、手工分组         |
| 平铺 | 等大卡片的整齐网格，文件夹在前，可按名称/类型/大小/修改时间排序（升/降）                       | 一眼看全、挑文件               |
| 列表 | 详细信息表：名称 / 类型 / 大小 / 修改时间 / 状态；点表头排序；文件夹可就地展开（缩进显示层级） | 文件很多、要看大小和时间       |
| 分组 | 平铺卡片按“文件类型 / 修改月份 / 计划状态”分栏，栏可折叠，栏内按当前排序                       | 先看有哪几类、哪些改动还没应用 |

在后三种里：单击选中并显示文件内容与解释，Ctrl 点选、Shift 选连续区间、方向键 / Home / End 移动，双击文件夹进入、双击文件用系统应用打开，拖到文件夹上即移入（拖到同层文件上即移出到那一层），右键菜单和筛选与画布一致。计划状态（待新建 / 待移动 / 待改名）以徽标显示，撤销、检查并应用等都不变。

- 三种新视图**不读取也不改动**画布上每张卡片的位置；切回画布，卡片原样在原处。
- 排序、分组方式和展示方式都存在 `preferences.json` 里，重启后保留。
- 图标大小对平铺和分组按同样比例缩放（用 CSS `zoom`，布局自然重排）；列表只缩放一半幅度，免得行高和字号变得过大。
- 预览懒加载：平铺和分组里的卡片用 IntersectionObserver，接近可见区域（上下各 300px）才读取缩略图或文档摘要；本机用 1000 个小文件实测，打开平铺只有 48 个预览，滚到底后 88 个。列表不用预览。
- 拖放与画布一致：不能把文件夹拖进自己或其内部的项（静默忽略，不弹错误）。
- 新手教程进行时会临时显示画布（不改你保存的展示方式），因为教程讲的是画布的操作。
- 实现：`domain/listing.ts` 是纯函数（计划状态徽标、排序、分组、列表行），`components/FileViews.tsx` 是三种视图的外壳；拖放用浏览器原生拖放（与画布的指针拖动互不影响），载荷沿用画布已有的 `application/x-filecanvas-nodes` / `application/x-filecanvas-source`，从左侧文件栏拖原始文件进来的处理与画布相同（这一条没有单独做界面测试）。

## 没有做的

- **主题色**：样式里仍有大量写死的绿色（对话框、AI 面板、规则编辑器等），只换令牌会出现新旧颜色混杂，需要先把这些颜色逐步迁到令牌上。
- **整个界面的缩放 / 文字大小**：窗口最小 1000×680 是按 100% 设计的，放大到 125% 以上会低于设计下限；本机内容区只有 1366×779，放大后连最小窗口都放不下。
- 深色模式。
