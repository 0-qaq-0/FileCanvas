## 启动

本机项目已有依赖，双击根目录 `启动开发版.cmd`。需要关闭时正常关闭软件窗口。

拿到源码包后先解压完整目录，保留根目录配置和编号文件夹。Windows 安装 Node.js 22.12 或更高兼容版本，在解压后的项目目录打开 PowerShell：

```powershell
npm.cmd ci
npm.cmd run dev
```

首次安装需要联网下载依赖和 Electron。以后可双击启动脚本。单独复制 `01_源码` 不能启动项目；ZIP 不带 `node_modules`。

`npm.cmd run build` 生成运行文件并检查类型，不生成 EXE。后续准备发布时再执行 `npm.cmd run package:win`，成品写入 `07_发布成品`。

## 整理到真实文件

1. 选择本地目录，将需要整理的文件加入画布。初次可先从欢迎页使用虚构样例，或使用自己小目录的一份副本。
2. 拖入目标文件夹、改名、新建分类文件夹。卡片上的“待移动 / 待改名 / 待新建”表示尚未写入本地；仅调整卡片坐标不会移动文件。
3. 点击固定的 **检查并应用**，核对本地目录、原路径、新路径和问题列表。有问题时先修改计划。
4. 点击 **应用到本地文件** 后执行真实移动。期间显示进度；结束时独立核对目录路径、文件身份和移动文件内容，通过后显示“已应用并核验”。

支持普通文件和已有文件夹移动、重命名、嵌套目录调整、父目录移动时对子文件重新分类，以及只改文件名大小写。移动已有文件夹前，需要将它的完整可读取子树加入项目；遗漏内容会在预览阻止应用。

预览后如果目录或计划又变了，需要重新检查。遇到同名目标不覆盖；当前也不支持靠交换名字或合并两个已有同名目录来消解冲突。

## 恢复、刷新和保存

- **画布撤销**：`Ctrl+Z` 撤销尚在画布里的整理计划，不会逆转已经发生的磁盘移动。
- **文件路径恢复**：通过 **更多工具 → 恢复上次文件移动** 打开记录，核对后恢复。界面只开放最近一次操作；更早记录会归档，未提供任意历史时间点回退。
- **执行中断**：再次打开目录时会提示待恢复任务，并阻止继续应用；使用恢复入口处理。无法核对文件身份或内容时保留记录并显示原因。
- **外部变化**：使用 **更多工具 → 刷新并核对** 查看新增、修改、缺失文件，确认后更新画布；尽量保留仍有效的整理计划。
- **项目保存**：自动保存画布、部分视图设置和展开状态。磁盘操作完成但项目记录未存好时，重开项目会尝试从操作记录补存。

开发运行的数据位置为 `%APPDATA%\FileCanvas-Development`；构建后普通运行使用 `%APPDATA%\FileCanvas`。其中 `projects` 保存画布，`operations` 保存最近操作与 `history` 归档。旧格式日志升级前保留 `.v1-backup`，旧项目格式继续兼容。

执行期间所选目录可能出现 `.filecanvas-operation-<任务ID>` 临时恢复区，正常完成后清理。任务未完成时保留它及软件数据目录。恢复区用硬链接保留路径操作所需文件身份，不是独立文件备份；它不能恢复文件正文的历史版本。

## 当前使用范围

| 项目       | 当前范围                                                                                                         |
| ---------- | ---------------------------------------------------------------------------------------------------------------- |
| 文件位置   | 同一授权根目录内的本地整理，文件系统须支持硬链接；主要验证环境为 Windows 本地 NTFS                               |
| 每次应用   | 最多移动 100 个文件；目录变化及其子文件计入实际执行范围                                                          |
| 目录规模   | 画布项目最多 5000 项，核对根目录最多 10000 项；数量上限不等于性能承诺                                            |
| 路径       | 目标完整路径限制 240 字符，沿用 Windows 名称约束                                                                 |
| 特殊目录   | 不支持跨盘、网络共享和链接/目录联接内的整理；没有跟随链接搬运内容                                                |
| 文件夹属性 | 当前通过建立目标目录、移动文件和移除空源目录完成整理；自定义目录权限、创建时间等元数据不保证原样迁移             |
| 恢复内容   | 恢复最近移动的路径；保留可辨认的无关新增或编辑。移动文件正文被外部改写时会阻止无法确认的恢复，不提供正文版本回退 |
| AI         | 可选；真实服务质量和费用未在本轮验证，PDF、Office、音视频正文提取尚未实现                                        |

第一次建议用少量真实文件副本走完“整理 → 应用 → 查看本地目录 → 恢复”。后续按实际使用反馈改进，不把这版描述为完整备份工具或已完成正式发布。

## 源码交付与维护

源码包包含源文件、锁定依赖版本的配置、已有检查、构建脚本、文档和虚构样例。不包含 `.git` 历史、`node_modules`、运行构建、历史 EXE、个人项目或 AI 配置。

运行 `npm.cmd run source:zip` 会在 `09_源码交付` 下新建带时间的交付目录，生成源码目录、ZIP、`SOURCE_MANIFEST.json` 和 `SHA256SUMS.txt`。清单记录文件摘要、版本和打包时的 Git 提交；清单自身不纳入文件摘要列表。每次新建输出，不覆盖之前的包。

当前仓库在 `feature/productization` 分支，建议后续按一个小功能一次提交保存版本。ZIP 是可独立安装依赖的源码快照，若从 ZIP 建立新仓库，可在解压目录重新初始化 Git。

当前 `package.json` 标记 `private: true`、`UNLICENSED`，尚未选择公开分发的开源许可证；这不会妨碍你继续修改自己的项目，但不应把本轮交付描述为已发布的开源项目。

下一轮最直接的工作是记录一次小目录的实际使用反馈，再集中修改阻碍使用的问题。EXE 打包、签名、版本升级/自动更新留到准备发布时进行。
