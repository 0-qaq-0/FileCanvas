# FileCanvas 0.3.0

> 本文说明之前发布的 0.3.0。当前开发版已有同屏展开、自动文件解释与受控的真实移动，见 [开发体验与验收](展开式整理_开发体验与验收.md)。

本说明中的命令和相对路径均以 `FileCanvas` 项目根目录为准。文件夹导航见根目录的 `README.md`。

一个真实运行的 Windows 文件整理演练台。**当前保持阶段一的原始文件只读边界。** 按名称/类型生成分类草案，在画布中微调，再对照结构并导出方案。程序没有对原始文件执行移动、重命名、创建目录或删除的接口。

## 先体验新流程

点击“更多工具 → 体验示例”，会在软件自己的 demo-runs 目录中创建并导入一份新的 20 文件副本，不覆盖已保存项目。使用“分类草案”选择内容项目或按类型分类，检查每项理由后采用；未知用途需人工确认。整份分类草案可以一次撤销。

选中卡片查看原位置与拟放位置。“预览变更”中可切换结构对照并导出 Markdown 方案；导出前重新检查磁盘，方案保存到软件自身 exports 目录。导出不包含文件内容，也不是可直接执行的脚本。“查看原文件夹”只在资源管理器中打开已授权的根目录。

样例实操见 [演示指南](../08_演示体验/README.md)，定位依据见 [竞品调研](产品调研/01_竞品调研与卖点判断.md)。

## 直接使用

Windows 10 / 11，x64。打包结果位于 `07_发布成品/FileCanvas-0.3.0-Windows-x64.exe`，双击运行，无需安装 Node.js。便携包启动时会先解压运行组件，首次启动稍慢。也可以运行 `07_发布成品/win-unpacked/FileCanvas.exe`，此方式需保留整个 `win-unpacked` 文件夹。

此开发版本未进行数字签名，也没有自动更新。系统可能展示未知发布者提示。不要以管理员身份运行；当前版本不需要提权。Windows 11 上已实际启动和自动验收，Windows 10 为目标兼容平台，尚未在独立 Windows 10 机器上验证。

1. 点击“打开文件夹”，选择具体的本地文件夹，会自动加入画布。读取失败时可分批加入。
2. 点击“文件栏”展开文件树、搜索、勾选多项，再点“加入画布”；也可以直接把文件栏中的文件拖到画布或虚拟文件夹卡片。
3. 拖动卡片自由排列。空白处拖动框选，Ctrl / Shift 多选并批量拖动。
4. 新建虚拟文件夹；把卡片拖进文件夹进行分类。双击文件夹进入，使用面包屑或返回按钮导航。“移动到…”可改变嵌套层级，“移至上级”可将选中条目移出当前目录。
5. 选中一项后按 F2 或点“重命名”。“移出画布”只移除虚拟对象，不删除真实文件，且可撤销。
6. 点击“预览变更”，核对原路径、目标路径、创建目录、重命名和冲突。可切换显示“无变化”的条目。

“打开文件夹”每次创建独立项目。“更多工具 → 已保存项目”可恢复已保存项目。软件启动时自动恢复上一次项目。

## 画布与 AI 新功能

打开文件夹后自动加入画布。单击卡片预览文字、图片或文件夹内部列表，F2 负责重命名。文件栏、内容预览和 AI 助手均可收起；专注画布可铺满窗口。模型配置、索引范围、发送资料与全电脑知识库研究见 [画布与 AI 改版说明](画布与AI改版说明.md)。

## 保存与快捷键

每次虚拟操作后自动保存；底部显示保存状态。Ctrl+S 可手动保存。正常关闭时，程序会等最后一次保存成功再关闭；保存失败会保留窗口并提示。强制结束进程、断电或磁盘故障仍可能丢失最近一次未保存操作。

项目位置：`%APPDATA%\FileCanvas\projects\`。每个项目一个 UTF-8 JSON，临时写入后替换完整快照；`last-project` 保存最近打开的项目 ID。Electron 的缓存也只写入自己的用户数据目录。项目文件不会写入选择的原始目录。为维持这一边界，不允许选择包含 FileCanvas 自身数据目录的过大根目录（例如整个系统盘或整个用户目录），请选具体子目录。

| 快捷键                | 功能                         |
| --------------------- | ---------------------------- |
| Ctrl+Z                | 撤销虚拟操作，包括布局       |
| Ctrl+Y / Ctrl+Shift+Z | 重做                         |
| Ctrl+S                | 保存项目                     |
| Ctrl+A                | 选中当前虚拟文件夹的所有条目 |
| F2                    | 重命名单个选中条目           |
| Escape                | 取消选择 / 关闭对话框        |
| Enter                 | 打开已聚焦的文件夹卡片       |

撤销历史保存于当前会话内，最多 80 步。关闭后保留最终结构与布局，**不保留撤销栈**。项目保存失败时请先处理底部提示，不能把“界面仍能操作”当作保存成功。

## 功能边界

- **布局与结构分离**：卡片 x/y 只用于当前层画布；parentId 和 name 决定目标路径。移动坐标不会变成磁盘操作。
- 源路径保持独立，源对象按规范绝对路径生成稳定 ID；重复导入会忽略已有对象，不重新安排已有位置。
- 导入真实文件夹会读取整个子树，保留原层级；部分文件先行单独导入后，之后导入其原父目录不会强行改变已有虚拟归属。
- 只导入的条目参与预览，未导入文件不在计划内。统计的是**变更条目**，不是一个可直接执行的有序移动脚本。
- 目录异步读取，画布按视口渲染。一个项目最多 5000 项；搜索最多遍历 10000 项、返回 300 项。当前版本未承诺任意规模目录的性能，推荐从几百项以内的目录开始。
- 不支持 UNC 网络路径、符号链接、目录联接、NTFS 备用数据流；文件夹内含不可读取或不支持的条目时，整批导入失败，不留下半个虚拟子树。
- 使用 Windows 不区分大小写的同名规则，拒绝保留名称、非法字符和末尾句点/空格；不支持启用大小写敏感的特殊 NTFS 目录语义。
- 目标路径超过 240 个字符会在预览标为问题；原路径或文件夹权限问题会提示。预览会检查存在性、类型、大小、修改时间和目标冲突。**大小+修改时间不是内容哈希**，不能据此保证外部修改一定能被发现。
- 已有目标即使可能由另一个计划移走，也保守标为冲突；不会推测可安全覆盖或交换名称。源文件发生变化时，建议核对后新建项目重新导入。
- 不提供系统默认程序打开真实文件、外部资源管理器拖入、导出项目、跨盘移动、云同步、缩放和平移或真实恢复。画布可通过滚动条浏览大范围布局。
- **“应用到硬盘”明确禁用。真实操作日志、真实恢复均未实现，也未作为已完成功能交付。**

## 源码运行与打包

需要 Windows 上的 Node.js 22.12+（本次使用 24.21.0）、npm 和可访问依赖下载源的网络。所有代码和文档使用 UTF-8。

```powershell
Set-Location 'D:\ai\a_小红书接单\FileCanvas'
npm.cmd ci
npm.cmd run dev
```

`dev` 自动构建 Electron 主进程和 preload，再启动 Vite 和桌面窗口。修改前端会热更新，修改 `01_源码/electron/` 后请退出并重新运行。开发模式只接受固定的本机 Vite 地址，正式打包使用本地资源和严格脚本 CSP。

依赖安装好后，也可双击工作区的“启动开发版.cmd”。源码已初始化 Git，适合每完成一个阶段做本地提交，避免后续增加真实文件操作时难以回退代码。

```powershell
# 生产构建、启动
npm.cmd run build
npm.cmd start

# 模型 / 文件系统测试
npm.cmd test

# 真实 Electron 交互验收（会自动开关测试窗口）
npm.cmd run test:e2e

# Windows x64 便携 EXE
npm.cmd run package:win

# 或只生成可运行目录
npm.cmd run package:dir
```

若当前终端设置过 `ELECTRON_RUN_AS_NODE`，手动执行 `npm.cmd start` 前应清除此环境变量，否则 Electron 会以 Node 方式运行。开发脚本与测试脚本会自动从子进程环境中移除它。依赖版本固定在 `package-lock.json`。

## 架构

```text
01_源码/electron/main.ts          窗口、来源验证、授权根目录、受控 IPC
01_源码/electron/preload.ts       contextBridge 白名单，无通用 Node/IPC 暴露
01_源码/electron/filesystem.ts    异步只读浏览、路径/链接检查、真实预览计算
01_源码/electron/storage.ts       自身数据目录的串行原子项目保存
01_源码/src/domain/types.ts       项目、源条目、虚拟节点、快照、预览类型
01_源码/src/domain/workspace.ts   纯虚拟事务、层级与名称校验、历史及布局
01_源码/src/components/Browser.tsx 目录树、搜索、选择、原文件拖入
01_源码/src/components/Canvas.tsx 指针拖动、框选、多选、视口渲染
01_源码/src/components/Dialogs.tsx 项目恢复、移动目的地、变更预览
01_源码/src/App.tsx               项目会话、自动保存、导航、快捷键
02_测试/                    领域/安全测试与真实 Electron 验收
```

Electron 配置：`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`、`webSecurity: true`。主进程检查 IPC 的 WebContents、主 frame 和页面来源，拒绝窗口弹出、跳转及页面权限申请。真实文件仅存在 list/search/import/preview 读取通道。所有写入都在固定软件数据目录内。采用 Electron 是为了 Windows 本地对话框、可靠路径检查、受控本地读写和独立可执行包；React/TypeScript 便于将可测试的虚拟模型与交互分离。拖动使用 Pointer Events，外部区域传入采用内部 MIME 的 HTML Drag & Drop，减少额外拖拽框架的层级和事件捕获冲突。

## 验收与后续阶段

见 [阶段一验收报告](阶段一验收报告.md)。自动验收会在系统临时目录创建 `filecanvas-e2e-*`，其中“原始测试文件”与“应用数据”分开放置；不使用用户重要文件。结果与截图写入工作区 `03_测试结果/`。为便于复查，临时样本会保留，确认不再需要后可手动删除对应测试目录。

阶段二需要另行验收：不可覆盖的执行计划、执行前重新授权与检查、逐步日志、失败停止、真实恢复前的内容核验与冲突拒绝。文件夹移动/重命名涉及祖先与子项依赖，不能把预览表逐行直接执行。阶段一通过后再决定是否开始这部分工作。
