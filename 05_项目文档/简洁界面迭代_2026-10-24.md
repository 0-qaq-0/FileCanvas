# 简洁界面迭代 · 2026-10-24

本轮针对 FileCanvas 0.5.0 的本地源码做易用性改版。已发布 EXE 未更新，Git 分支为 `feature/simple-file-ui-20261024`。

## 体验方式

在项目根目录双击 `体验简洁新版.cmd`，或运行 `npm.cmd run preview:simple`。会先检查并构建，再打开真正的 Electron 窗口，并自动创建一份 20 文件的虚构示例。每次使用独立体验目录，保存在项目内 `03_测试结果/简洁界面体验`，便于比较；不会覆盖正式版或开发版保存的项目和 AI 配置。可关闭窗口后再次运行。

体验窗口中的操作都是真实可用的，点击“应用到本地文件”会实际整理示例副本。普通 `npm.cmd run dev` 使用原来的开发配置；先前保存的显示偏好继续保留，新配置默认关闭整理建议条与底部提示。

## 本轮做的减法

| 原来的问题                              | 当前行为                                                     |
| --------------------------------------- | ------------------------------------------------------------ |
| 顶部同时出现 AI、文件栏、设置与多种操作 | 只突出打开、分类、撤销/重做、预览应用，辅助工具收到“更多”    |
| 画布、平铺、列表、分组四项常驻          | 默认展示画布和列表；其他视图在设置里选择，选中后显示当前模式 |
| 正常状态和重复提示占用空间              | 正常状态合并到路径导航，变化与错误才展开提示条               |
| 分类一次给出五张规则卡                  | 默认按类型，一个下拉框选择其他方式，保留逐组预览和开关       |
| 单击文件就挤出内容/AI 面板              | 单击只选择，主动点眼睛或“预览详情”；AI 收起且按需运行        |
| 文件类型主要靠缩略图和英文后缀辨认      | 图形、颜色、中文类型与扩展名共同表示；图片保留缩略图         |

文件夹用独立的金色文件夹图形，卡片显示递归文件数量、子文件夹数量、合计大小和最常见两类内容。展开后的容器也显示文件数量和大小，详细列表与预览共用同一份统计口径。大小使用 B/KB/MB/GB/TB，未知值单独标明。

**统计范围是当前画布内的已导入文件**，包括嵌套内容，不代表文件夹的全部磁盘占用，也不读取额外文件。摆放只改坐标，拖入文件夹才改分类；所有真实移动仍走预览、冲突检查、应用、核验和恢复的原有流程。卡片基础尺寸及已存布局坐标不变。

## 右键菜单补充迭代

| 右键位置 | 可用操作                                                                                    |
| -------- | ------------------------------------------------------------------------------------------- |
| 单个文件 | 预览详情、系统打开、在资源管理器中显示、移动到、移入新文件夹、重命名、移出画布              |
| 文件夹   | 预览详情、打开、展开/收起、移动、改名、新建子文件夹、移出画布；已有来源才显示资源管理器入口 |
| 多选文件 | 移动到、移入新文件夹、批量重命名、移出画布；右键已选项保留整组选中，右键未选项切为单项      |
| 空白处   | 新建文件夹、全选当前层或匹配项、画布排列、展开/收起、添加文件、撤销/重做计划、刷新核对      |

顶部移除了“新建文件夹”，选中浮动栏缩为数量、操作和取消。“操作”按钮打开文件菜单，“画布选项 / 视图选项”打开对应空白菜单，因此不依赖右键也能完成操作。菜单显示必要的快捷键；`Shift+F10` 可打开，方向键、Home/End 可选择并跳过禁用项，Esc 关闭，菜单会在窗口边缘自动调整位置。

新建子文件夹在对话框中明确显示目标，防止新建到当前层。“移出画布”注明“不删除本地文件”，仍可 Ctrl+Z 撤销。没有增加真实删除或绕过预览直接操作磁盘的入口。

## 参考案例与实际采用的做法

- [Apple Finder：文件夹展示方式与显示选项](https://support.apple.com/en-au/guide/mac-help/mchldaafb302/mac)：图标视图便于辨认内容，列表展示大小、类型等信息，详细选项按需打开。本轮采用图标加摘要、列表加明确元信息的层次；没有复制其界面素材。
- [NN/g：Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)：优先展示常用功能，需要时再展开次要选项。本轮用于辅助工具菜单、分类方式、画布选项和 AI 区域。

## 第三轮减法 · 2026-10-27

| 原来的问题                                                               | 当前行为                                                                                                                                                                                                       |
| ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 新卡片固定排 5 列，宽屏右侧空一大片，小窗口要横向滚动                    | 新导入、新建和分类结果按当前画布宽度排列；“排列整齐”同样不超出可视宽度。已经摆好的卡片不会被自动挪动                                                                                                           |
| 按类型分类时 10 个文件常拆成 8 个单文件文件夹                            | 默认勾选“零散类型合并到“其他””：已有成组的类型时，只有 1 个文件的类型并入“其他”；画布上已有同名文件夹的仍直接放入。所有类型都只有 1 个文件时保持按类型。这个开关只在合并确实改变结果时出现，避免勾着却没有效果 |
| 卡片上类型说了三遍（“表格 · XLSX”、图标角标、文件名后缀）                | 左上角只写中文类型（表格、代码、PDF）                                                                                                                                                                          |
| 文件夹卡片有“文件夹”标签、与名称重复的类型、文件数角标和每张都带“画布内” | 去掉这些重复；主要类型与名称相同就不显示；空文件夹直接写“空文件夹”；统计范围放在悬停说明里                                                                                                                     |
| “尚未应用”同时是一整行横幅、按钮数字和卡片标记                           | 横幅收进路径栏的小标签“尚未应用 · 本地文件未改动”，横幅只在出错和教程时出现                                                                                                                                    |
| 画布左上角常驻“项目根目录 拖到容器外，放回这里”                          | 去掉；拖动时顶部的去向提示已经说明放到哪里                                                                                                                                                                     |
| 顶部“整理画布 · 10 项”和底部“11 个文件”看起来矛盾                        | 分别写“本层 10 项”和“共 11 个文件”，底部悬停说明包括文件夹里的内容                                                                                                                                             |
| 应用前预览以“16 待变更条目 / 6 路径未改变”开头                           | 改成“8 移动 · 8 新建文件夹”，只有冲突时才显示“需要处理”；范围说明缩成一行，完整说明在悬停提示里                                                                                                                |

真实移动仍走预览、冲突检查、应用、核验和恢复的原流程，本轮没有改动磁盘操作代码。分类合并规则由子代理实现并补了单元测试（`drafts-merge.test.ts`），主流程复核后把“其他”固定排在分组列表最后。桌面检查的示例每类只有 1 个文件，只验证开关隐藏；合并本身由单元测试覆盖。打开窗口后再缩小，已摆好的卡片仍可能需要横向滚动，这是自由摆放的规则，点“排列整齐”即可收拢。

## 检查与证据

- `npm.cmd run build`：TypeScript、Vite 和 Electron 主进程构建通过。
- `npm.cmd test`：248 项单元检查通过（第三轮新增 8 项分类合并检查）。
- `npm.cmd run test:simple`：在真实 Electron 内检查欢迎页、类型与容量、嵌套统计、右键单项改名、多选归类、子文件夹新建、嵌套目标、移出画布保留原文件、空白菜单、禁用项与键盘、1000×680 边缘定位、按需预览、视图切换、分类草案、真实应用、恢复及教程。第三轮补充：新卡片在 1280 宽窗口至少排 7 列且画布无横向滚动，1000 宽窗口排列后无横向滚动，卡片不再重复类型文字，待应用标签替代横幅，预览按“移动 / 新建文件夹”计数。
- 桌面检查用项目内的虚构样例。应用后比较全部文件 SHA256，恢复后比较目录和文件哈希；结果与截图在 `03_测试结果/简洁迭代/验收.json` 及同目录 PNG。

此前的专项桌面脚本有部分仍基于旧按钮名称和单击预览行为，本轮以 `test:simple` 为界面验收入口。未实测真实 AI 服务、大规模目录或更新后的 EXE，不能把本轮结果当作这些场景的验证。
