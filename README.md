# FileCanvas 0.5.0 · Windows 文件整理画布

先在画布中整理，再确认应用到真实文件。支持本地文件与文件夹的移动、重命名、新建分类目录，应用前核对路径，应用后核验，并可恢复最近一次文件移动。

**源码比已发布的 0.5.0 EXE 新**：简洁界面和后续的稳定性改进都在“未发布”阶段，内容见 [CHANGELOG](CHANGELOG.md)。双击根目录的 `体验简洁新版.cmd` 即可构建并打开独立示例窗口，详见 [改版说明与参考案例](docs/简洁界面迭代_2026-10-24.md)。下面的说明以源码为准。

## 下载与使用

到 [Releases](https://github.com/0-qaq-0/FileCanvas/releases/latest) 下载 `FileCanvas-0.5.0-Windows-x64.exe`，双击即可运行，无需安装 Node.js。同一页附有 SHA256 校验值。

- 目前是 Windows x64 免安装版，**未做代码签名**，Windows 可能提示来源。
- 首次建议点击“试用示例文件”，示例是程序生成的虚构文件，不会碰你的真实资料。本地试用入口会自动打开示例。
- 整理自己的资料时，先用少量副本。范围是同一授权本地目录，建议 NTFS；不支持跨盘、网络共享和符号链接/目录联接。
- 一个项目最多容纳 5000 个条目，一次可以全部应用（已发布的 0.5.0 仍是一次 100 个文件）。超过 5000 项的文件夹会先加入最近修改的部分，并说明其余的；内容过多、含链接或无法读取条目的子文件夹可以打开，但暂时不能整体移动。
- 欢迎页的“开始新手教程”约 1 分钟，也可随时从“更多工具”重看。

## 能做什么

1. 打开本地文件夹（欢迎页可直接“整理下载 / 整理桌面”，也可以把文件夹拖进窗口；“打开文件夹”菜单里有最近的项目），直接在画布中查看；常用视图只保留画布和列表，平铺、分组在界面设置内选择。
2. 拖动归类、改名、新建文件夹，或点击 **自动分类**，默认按文件类型。月份、归档和“我的规则”在分类方式下拉框中选择。卡片会显示待移动、待改名、待新建；排列卡片只改画布位置。
3. 点击顶部 **预览并应用**，核对原路径、目标路径和结构对照，再点击 **应用到本地文件**。
4. 完成后弹出“整理完成”报告，显示移动数量和整理前后对比，可保存对比图（默认不显示文件名）。需要放回去时，使用 **恢复上次文件移动**。

`Ctrl+Z` 撤销画布计划；已经应用到磁盘的移动使用专门的恢复入口。外部新增、删除或修改文件后，路径栏会提示“文件夹有 N 处变化”，点它或按 `F5` 核对后再决定是否更新；刷新不会把你“移出画布”的条目加回来。`Ctrl+O` 打开文件夹，也可以随时把文件夹拖进窗口；再次打开同一个文件夹会回到它的项目。图标大小、画布背景、对齐网格等在 **更多工具 → 界面设置**（`Ctrl+,`）里调整。单击文件只选择，点击眼睛或“预览详情”查看内容；文件夹统计仅涵盖已经加入画布的内容。

**右键操作**：文件可预览、改名、移动到或移入新文件夹；多选后右键批量处理；文件夹还能展开、进入或新建子文件夹；空白处右键新建、全选和排列。选中浮动栏只保留数量、“操作”和取消；不使用右键时点“操作”或“画布选项 / 视图选项”即可。“移出画布”只移除整理计划条目，不删除本地文件。也支持 `Shift+F10` 打开菜单及方向键选择。

**文件集**：不想移动文件、只想把相关文件归在一起时，右键文件选“加入新文件集…”或“加入‘某个文件集’”，也可以把卡片拖到画布顶部的文件集上；选中文件夹会加入其中已在画布上的文件。同一个文件可以放进多个文件集，卡片角上显示它在几个文件集里。文件集的“⋯”菜单可以打包为 ZIP、复制到文件夹（原文件留在原处），或“收进新文件夹”（和其他整理一样，预览并应用后才移动，可以恢复）。在别处改名或删除的文件会被标出，打包和复制时跳过，并可一键移除。

## 配置 AI（可选）

文件整理不依赖 AI。需要文件解释与位置推荐时，打开 **更多工具 → AI 助手 → 配置模型**，在“常用服务”里选 OpenAI、DeepSeek 或本机 Ollama，也可以填兼容接口、自己的密钥并测试连接。密钥由系统加密保存在本机；首次分析需允许本项目把相关文本发送给你配置的服务。文件预览里的 AI 区域默认收起，展开并授权后才分析。

当前主要读取文本、代码和文件元信息，PDF、Office、音视频尚未提取正文。DeepSeek 官方接口已用程序自己的 AI 代码实测过连接、文件解释和分类方案（2026-10-21）；其他服务的回答质量和费用需要自己核实。

## 从源码运行

需要 Node.js 22.12 或更高的兼容版本，在项目目录打开终端：

```powershell
npm.cmd ci
npm.cmd run dev          # 开发版，使用独立的 %APPDATA%\FileCanvas-Development
npm.cmd run build        # 检查类型并构建运行文件，不生成 EXE
npm.cmd run typecheck    # 类型检查
npm.cmd run lint         # ESLint（错误会失败；Hook 依赖只作提醒）
npm.cmd run format:check # 格式检查
npm.cmd test             # 单元检查
npm.cmd run test:desktop # 构建后依次运行全部桌面检查
npm.cmd run preview:simple # 构建并打开独立示例体验窗口
npm.cmd run package:win  # 生成 Windows x64 免安装 EXE（输出到 release）
```

打包前留意：输出文件名只由版本号决定，版本号不变时会覆盖 `release` 里同名的已发布 EXE。试打包可以先改版本号，或加 `-c.directories.output=其他目录`。

桌面交互检查用 Playwright 驱动真实的 Electron 窗口，共用的操作在 `tests/e2e/ui-helpers.mjs`，结果写入 `test-results`。也可以单独运行：

| 命令                                        | 涵盖                                                         |
| ------------------------------------------- | ------------------------------------------------------------ |
| `test:simple`                               | 简洁界面、右键菜单、分类、真实应用与恢复、完成报告           |
| `test:maturity`                             | 超大文件夹、外部变化、保存失败时关窗、页面崩溃恢复、窗口记忆 |
| `test:sets`                                 | 文件集：加入、拖入、打包、复制、找不到的文件、收进文件夹     |
| `test:e2e`、`test:demo`、`test:smart`       | 基本流程、示例副本、我的规则与批量重命名                     |
| `test:views`、`test:settings`               | 四种视图、界面设置                                           |
| `test:tutorial`、`test:ai`、`test:expanded` | 新手教程、AI（本机模拟服务）、同屏展开文件夹                 |

中断恢复单独用 `node tests/e2e/recovery-crash.mjs` 运行，它也包含在 `test:desktop` 里。页面崩溃恢复由 `crash-reload-main.cjs` 在不接 Playwright 的真实 Electron 中验证，因为 Playwright 的调试器会让崩溃后的新页面停住。打包后的检查是 `tests/smoke` 里的 `smoke-package.mjs --demo` 和 `smoke-portable.ps1`。

推送到 GitHub 后，`.github/workflows/ci.yml` 会在 Windows 上运行类型、ESLint、格式、单元检查和 `test:simple`。

出问题时，**更多工具 → 使用说明** 底部可以看到版本号和数据位置，并能打开日志文件夹。日志只保存在本机，记录错误信息（可能包含文件名），不含文件正文和密钥。

## 项目位置

| 目录           | 内容                                               |
| -------------- | -------------------------------------------------- |
| `app`          | React 界面、Electron 主进程、文件操作与存储、图标  |
| `tests`        | 单元测试与桌面交互检查                             |
| `test-results` | 本机检查证据与截图（不进入 Git）                   |
| `scripts`      | 开发启动、构建、源码打包脚本                       |
| `docs`         | 当前说明、规划、调研及历史审查记录                 |
| `dist`         | 自动生成的运行文件（不进入 Git）                   |
| `release`      | 本地打包输出（不进入 Git），EXE 通过 Releases 分发 |
| `demo`         | 原创虚构样例和演示步骤                             |
| `source-zip`   | 本地生成的源码包（不进入 Git）                     |

EXE 使用 `%APPDATA%\FileCanvas`，开发版使用 `%APPDATA%\FileCanvas-Development`，两者的画布项目和 AI 配置不会自动同步。详细的更新内容见 [CHANGELOG](CHANGELOG.md)。
