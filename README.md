# FileCanvas 0.4.0 · 源码开发版

先在画布中整理，再确认应用到真实文件。当前版本支持本地文件与文件夹移动、重命名、新建分类目录、最近一次文件移动恢复，以及外部文件变化的刷新核对。

本轮交付源码，未制作新版 EXE。`07_发布成品` 中的 0.3.0 是历史版本，不包含这些改动。当前使用方式、限制和已有检查见 [0.4.0 源码版使用与交付说明](05_项目文档/0.4.0源码版使用与交付说明.md)，更新内容见 [CHANGELOG](CHANGELOG.md)。

## 开始使用

本机已安装依赖，可双击 [启动开发版.cmd](启动开发版.cmd)。复制源码到另一台 Windows 电脑后，需要先安装 Node.js（22.12 或更高的兼容版本），在项目目录打开终端运行：

```powershell
npm.cmd ci
npm.cmd run dev
```

1. 打开一个本地小目录，把需要整理的文件加入画布。初次使用也可以从欢迎页打开虚构样例。
2. 拖动文件到目标文件夹，或改名、新建文件夹。卡片显示待移动、待改名、待新建；自由摆放卡片只改变画布位置。
3. 点击顶部 **检查并应用**，核对原路径、目标路径和问题提示，然后点击 **应用到本地文件**。
4. 完成后查看“已应用并核验”。需要恢复路径时，打开 **更多工具 → 恢复上次文件移动**。

`Ctrl+Z` 撤销画布计划；已经应用到磁盘的移动使用专门的恢复入口。外部新增、删除或修改文件后，使用 **更多工具 → 刷新并核对**，确认变化后更新画布。

当前以支持硬链接的本地文件系统为范围，建议先在 NTFS 小目录使用；一次最多移动 100 个文件。详细范围和恢复限制请先看当前说明。

## 配置 AI（可选）

文件整理不依赖 AI。需要文件解释与推荐时，打开 **AI 助手 → 配置模型**，填写自己的服务地址、模型和密钥，测试连接；首次分析需允许本项目发送资料。支持兼容接口及本地 Ollama。

当前主要读取文本、代码和文件元信息，PDF、Office、音视频尚未提取正文。交互流程用本机模拟服务检查过，真实模型的回答质量与费用需要使用自己的服务核实。

## 项目位置

| 目录          | 内容                                              |
| ------------- | ------------------------------------------------- |
| `01_源码`     | React 界面、Electron 主进程、文件操作与存储、图标 |
| `02_测试`     | 已有单元测试与桌面交互检查                        |
| `03_测试结果` | 本机检查证据与截图，不随源码包分发                |
| `04_构建脚本` | 开发启动、构建、源码打包脚本                      |
| `05_项目文档` | 当前说明、规划及历史审查记录                      |
| `06_构建产物` | 自动生成的运行文件                                |
| `07_发布成品` | 历史 EXE；本轮未更新                              |
| `08_演示体验` | 原创虚构样例                                      |
| `09_源码交付` | 可独立安装依赖的源码目录、ZIP、校验值             |

开发项目和操作记录在 `%APPDATA%\FileCanvas-Development`，不在源码目录里。源码包不包含个人项目、密钥、依赖、EXE 或测试产生的临时文件。

## 后续维护

```powershell
npm.cmd run build       # 检查类型并构建运行文件，不生成 EXE
npm.cmd test            # 已有单元检查，需要时再跑
npm.cmd run source:zip  # 生成新的源码交付包
```

后面准备交付 EXE 时，再使用已有 `package:win` 命令。源码已在 Git 的 `feature/productization` 分支维护；每完成一个可用小改动保存一次提交，方便找回。
