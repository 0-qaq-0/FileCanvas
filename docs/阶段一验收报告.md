日期：2026-10-16（Asia/Shanghai）。范围：安全只读 MVP。

Windows 11，x64；Node.js 24.21.0，Electron 39.8.10，React 19.3.1，Vite 7.3.7。安装版本以 package-lock.json 为准。Windows 10 尚未在独立机器上验收。

- TypeScript 检查及生产构建通过。
- 29 项领域模型、文件系统、项目存储测试通过，包括 1605 个条目的默认布局范围检查。
- 真实 Electron 交互验收通过，渲染进程未出现未捕获错误。
- Vite + Electron 开发模式启动通过。打包后 `win-unpacked/FileCanvas.exe` 启动检查通过：`app.isPackaged` 为 true，数据路径为 `%APPDATA%\FileCanvas`，渲染进程无 require，真实应用按钮禁用。
- 最终 Windows x64 便携 EXE 已独立启动，并通过“窗口刚出现即关闭”和“正常加载后关闭”两次进程退出检查。文件大小 86,761,657 字节，未数字签名。SHA256 与结果记录在 `test-results/portable-smoke.json`。
- 已目视检查画布、预览及 1000×680 紧凑窗口截图；页面无整体水平溢出，画布自身可滚动。

## A：虚拟整理与持久化

专用临时根目录包含 10 个文件、2 个原始子文件夹。测试真实左栏拖拽及勾选批量导入，创建“图片”，移动 A.jpg；其他文件保留源映射。保存、关闭 Electron、重新启动，验证 10 文件计数、虚拟父级及坐标恢复。

整理过程中前后逐项比较路径列表、文件大小、mtime 和 SHA256；结果一致。测试最后再由测试脚本主动创建目标冲突、删除测试源文件，以模拟外部变动。这些改变与“软件整理保持源目录不变”的验证分开执行，均仅发生在专用测试目录。

## B：自由布局

真实鼠标框选两张卡片并批量移动，检查两者位移一致；通过 Ctrl+Z / Ctrl+Y 撤销重做。文件夹内连续拖动 8 次，往返导航后坐标一致。应用重启后再次检查坐标。

测试中发现并修复：指针捕获影响双击进入文件夹；批量导入默认位置可能遮住已有卡片。新增自动找空位和仅拖动时捕获指针。画布使用视口筛选与子项计数缓存。

补充启动边界：窗口刚出现就关闭时，渲染端可能尚未注册保存握手。现在在初始化前直接等待主进程保存队列并关闭，初始化后则先让界面提交最后快照；专用关闭测试覆盖这两个状态。默认布局在大批量导入时按区块延展，自动排列按条目数量扩展列数，避免超出坐标上限。

## C：真实结构推导预览

把 A.jpg 虚拟放进“图片”，预览实际显示：

```text
原路径：<专用测试根目录>\A.jpg
目标路径：<专用测试根目录>\图片\A.jpg
```

同时显示“图片”为新建目录，B.jpg 为路径无变化（可切换显示）。验证原文件仍在原路径且目标文件尚不存在。布局操作不会增加路径变更。

## 证据与复现

运行 `npm.cmd test` 和 `npm.cmd run test:e2e`。最后一次自动交互结果保存在 `test-results/acceptance.json`，其中记录测试根目录与逐项结果。截图为 `workspace.png`、`preview.png`、`compact.png`。这些文件由运行生成，未纳入 Git。

打包后启动检查脚本为 `node scripts/smoke-package.mjs`；首次使用空的应用数据目录时验证欢迎页。开发模式检查为 `node scripts/smoke-dev.mjs`。对应输出为 `package-smoke.json`、`dev-smoke.json` 与 `packaged-startup.png`。

便携包独立进程测试可运行 `& .\scripts\smoke-portable.ps1`，先退出已打开的 FileCanvas。源码关闭握手测试为 `node scripts/smoke-close.mjs`，输出 `close-smoke.json`。
